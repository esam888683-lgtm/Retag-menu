# حلال فور يو — المينيو الإلكتروني

مينيو إلكتروني للمطاعم، مبني بـ HTML + CSS + JavaScript فقط (بدون أي Framework)، مع سلة مشتريات، Checkout، وإرسال الطلب مباشرة عبر واتساب.

## 1. تشغيل المشروع

المشروع عبارة عن ملفات ثابتة (Static Files)، افتح `index.html` مباشرة في المتصفح، أو — للحصول على أفضل تجربة (خاصة مع الصور) — شغّل سيرفر محلي بسيط من داخل مجلد المشروع:

```bash
# باستخدام بايثون
python3 -m http.server 8000

# أو باستخدام Node
npx serve .
```

ثم افتح `http://localhost:8000` في المتصفح.

## 2. أين تغيّر اسم المطعم، اللوجو، والشعار؟

كل بيانات المطعم في مكان واحد فقط: أعلى ملف `js/app.js`، داخل `restaurantConfig`:

```javascript
const restaurantConfig = {
    name: "حلال فور يو",
    slogan: "تاكل وانت مطمن",
    logo: "assets/logo.svg",
    whatsappNumber: "201000000000",
    currency: "ج.م",
    deliveryFee: 25,
    primaryColor: "#7A1F2B"
};
```

- **الاسم**: غيّر `name`.
- **الشعار (Slogan)**: غيّر `slogan`.
- **اللوجو**: استبدل ملف `assets/logo.svg` (أو أي صورة) وحدّث المسار في `logo`.

## 3. أين تغيّر رقم واتساب؟

من نفس الكائن أعلاه فقط، القيمة `whatsappNumber`. اكتب الرقم بصيغة دولية بدون `+` وبدون صفر في البداية:

```javascript
whatsappNumber: "201012345678" // رقم 010 1234 5678
```

**لا يوجد مكان آخر في المشروع يحتوي على رقم الواتساب** — التغيير هنا فقط كافٍ.

## 4. مناطق التوصيل وأسعارها

كل منطقة توصيل بيتاح اختيارها للعميل، وسعرها، بيتحددوا من مكان واحد فقط: `deliveryAreas` داخل `restaurantConfig` في `js/app.js`:

```javascript
deliveryAreas: [
    { id: "nasr-city", name: "مدينة نصر", fee: 25 },
    { id: "heliopolis", name: "مصر الجديدة", fee: 30 }
]
```

- **لإضافة منطقة جديدة**: أضف سطرًا جديدًا بنفس الشكل. الـ `id` لازم يكون فريد (حروف إنجليزية بدون مسافات).
- **لتغيير سعر التوصيل لمنطقة**: غيّر قيمة `fee` الخاصة بها.
- **لحذف منطقة**: احذف السطر بالكامل.

العميل هيلاقي القائمة دي تظهر تلقائيًا كـ Dropdown في صفحة إتمام الطلب لما يختار "توصيل"، وسعر التوصيل بيتحسب ويتضاف على الإجمالي فورًا حسب المنطقة اللي هيختارها — من غير أي تعديل في HTML.

## 5. كيف تضيف قسم (Category) جديد؟

افتح `data/menu.js` وأضف عنصرًا جديدًا في مصفوفة `categories`:

```javascript
{ id: "desserts", name: "حلويات", icon: "🍮", order: 8 }
```

- `id`: معرف فريد بالإنجليزية (يُستخدم لربط المنتجات بالقسم).
- `order`: يتحكم في ترتيب ظهور القسم في الشريط العلوي.

## 6. كيف تضيف صنف (Product) جديد؟

في نفس الملف `data/menu.js`، أضف عنصرًا جديدًا في مصفوفة `products`:

```javascript
{
    id: 20,
    category: "desserts",
    name: "أم علي",
    description: "أم علي ساخنة بالمكسرات والقشطة",
    price: 60,
    image: "assets/products/desserts.svg",
    badge: null,
    available: true,
    extraGroups: []
}
```

- `id` يجب أن يكون رقمًا فريدًا غير مستخدم من قبل.
- `category` يجب أن يطابق `id` أحد الأقسام في `categories`.
- لا حاجة لتعديل أي HTML — الصنف سيظهر تلقائيًا.

## 7. كيف تعدّل السعر؟

غيّر قيمة `price` الخاصة بالمنتج مباشرة في `data/menu.js`. السعر النهائي المرسل في الطلب يُحسب دائمًا من هذا الملف، وليس من أي إدخال يكتبه العميل، لضمان دقة الفواتير.

## 8. كيف تضيف Extra (إضافة) جديدة؟

الإضافات مجمّعة في مجموعات (`extraGroups`) داخل `data/menu.js` لإعادة استخدامها بين أكثر من منتج:

```javascript
const extraGroups = {
    sauces: {
        id: "sauces",
        title: "الصوصات",
        type: "multiple", // أو "single" لاختيار واحد فقط
        options: [
            { id: "extra-garlic", name: "صوص ثوم", price: 10 }
        ]
    }
};
```

ثم اربط المجموعة بالمنتج عبر `extraGroups: ["sauces"]` داخل تعريف المنتج.

## 9. كيف تغيّر الألوان؟

الألوان الأساسية معرّفة في أعلى ملف `css/style.css` داخل `:root`:

```css
:root {
    --primary: #7A1F2B;   /* اللون الأساسي (أزرار، عناوين) */
    --gold: #C89B3C;      /* لون الشارات والتفاصيل الذهبية */
    --bg: #FBF7EF;        /* خلفية الصفحة */
}
```

كما يمكنك تغيير `primaryColor` في `restaurantConfig` (يُطبَّق تلقائيًا على متغير `--primary`).

## 10. رفع المشروع على GitHub Pages

1. أنشئ مستودع (Repository) جديد على GitHub وارفع محتويات هذا المجلد إليه.
2. من إعدادات المستودع، اذهب إلى `Settings > Pages`.
3. تحت `Source`، اختر الفرع `main` والمجلد `/root`، ثم احفظ.
4. بعد دقيقة أو دقيقتين، سيكون الموقع متاحًا على رابط بالشكل:
   `https://username.github.io/repo-name/`

## 11. تثبيت المينيو على موبايل العميل (PWA) وتحديث الأسعار تلقائيًا

المشروع فيه دلوقتي زرار "📱 تثبيت المينيو" بيظهر في أعلى الصفحة، وبيسمح للعميل يضيف المينيو على الشاشة الرئيسية لموبايله زي أي تطبيق عادي:

- **على أندرويد**: الزرار بيفتح نافذة تثبيت المتصفح مباشرة (Add to Home Screen التلقائي من Chrome).
- **على آيفون**: نظام iOS ميدّيش الإذن للمواقع تفتح نافذة تثبيت تلقائية، فالزرار بيفتح شرح خطوة بخطوة لعمل "إضافة إلى الشاشة الرئيسية" من قائمة المشاركة في Safari.

### إزاي التحديثات (الأسعار / الأصناف الجديدة) بتوصل للعميل تلقائيًا

الملف `service-worker.js` هو المسؤول عن التخزين المؤقت (Cache) اللي بيخلي المينيو يفتح بسرعة حتى لو النت ضعيف. لكنه مصمم عشان **الملفات المهمة** (`data/menu.js`, `js/app.js`, `index.html`, `manifest.json`) تتحمل دايمًا من الإنترنت أولًا (Network-First) وليس من نسخة قديمة محفوظة.

بالإضافة لكده، الموقع بيتحقق بنفسه من وجود تحديث في `data/menu.js` (من غير ما يعتمد بس على سلوك المتصفح):

- أول ما التطبيق يتفتح.
- كل مرة العميل يرجع للتطبيق (يطلع منه ويرجعله تاني).
- كل ما النت يرجع تاني بعد انقطاعه.
- كل 5 دقايق تلقائيًا لو التطبيق فاضل مفتوح.

لو لقى فرق حقيقي، هيظهرله شريط صغير أعلى الشاشة: **"في تحديث جديد للمينيو 🎉 [تحديث الآن]"** — والعميل بيضغط عليه براحته (مش تحديث إجباري عشان لو في نص طلب ميضيعش عليه).

هي الطريقة دي مضمونة أكتر من الاعتماد على تحديث الـService Worker لوحده، لأن التطبيقات المثبتة أحيانًا بترجع من الذاكرة (Resume) بدل ما تعمل تحميل جديد للصفحة.

### ملاحظات

- الـPWA بيشتغل بس لو الموقع مرفوع عبر `https://` (أو `localhost` وقت التجربة) — مش هيشتغل لو فتحت الملف مباشرة من جهازك (`file://`).
- لو عدّلت في قائمة الملفات الأساسية اللي بيحتفظ بيها الموقع للعمل بدون نت (`STATIC_ASSETS` في `service-worker.js`)، يفضل تغيّر قيمة `VERSION` أعلى نفس الملف عشان تتأكد كل الأجهزة تاخد النسخة الجديدة من كل حاجة.

## 12. هيكل المشروع

```text
restaurant-menu/
├── index.html          ← الهيكل (HTML فقط، بدون بيانات صلبة)
├── css/style.css        ← التصميم بالكامل
├── js/app.js             ← منطق التطبيق (السلة، الـCheckout، واتساب)
├── data/menu.js           ← الأقسام والمنتجات والإضافات (عدّل هنا فقط)
├── assets/
│   ├── logo.svg
│   └── products/          ← صور توضيحية لكل قسم (استبدلها بصور حقيقية)
└── README.md
```

## 13. ملاحظات للتوسع المستقبلي

الكود مقسّم بوضوح بين البيانات (`data/menu.js`)، والواجهة (`index.html` + `css/style.css`)، والمنطق (`js/app.js`)، والإعدادات (`restaurantConfig`) — لتسهيل أي تطوير مستقبلي مثل:

- ربط البيانات بـ Backend أو Firebase بدلاً من `menu.js`.
- إضافة نظام دفع إلكتروني عند تأكيد الطلب.
- بناء لوحة تحكم (Admin Panel) لتعديل الأصناف من واجهة رسومية.
- دعم أكثر من مطعم أو أكثر من لغة.

السلة تُحفظ حاليًا في `localStorage` بالمتصفح، لذا لا تختفي إذا أغلق العميل الصفحة وعاد لاحقًا.
